# Dreaming

Run one bounded memory-consolidation pass inside `self/` (all paths below are
relative to that directory), following the shared
Goated contract. The default schedule is every eight hours, not continuous work.

1. Read `MEMORY.md`, relevant user/VAULT notes, and the last successful checkpoint
   in `dreams/state.md`. Review a bounded window of retained conversations, daily
   notes, and mission logs since that checkpoint; on a first run start with the
   last eight hours. Record any unprocessed backlog instead of claiming full coverage.
2. Identify durable decisions, preferences, commitments, outcomes, and lessons.
   Keep source paths or message references and dates. Separate confirmed facts
   from hypotheses; repeated copies of one source are not corroboration.
3. Reconcile the canonical notes in place: merge duplicates, supersede stale
   facts with evidence, and flag unresolved contradictions. Keep `MEMORY.md`
   short; put detailed knowledge in `VAULT/`, linking relevant goals and missions.
   Follow the OKF-inspired convention in `../../docs/KNOWLEDGE_FORMAT.md`.
4. Re-read each target before editing so concurrent mission/heartbeat updates
   are preserved. Make targeted edits, verify the result, and keep useful history
   and source pointers. Do not bulk-delete source material.
5. Write a dated report under `dreams/`: sources and time window examined,
   changes, uncertainties, failures, and remaining backlog. Advance
   `dreams/state.md` only through successfully processed material; partial failures
   must remain retryable. A no-op needs no rewritten knowledge.

Dream reports, retrieved envelopes, and prior reflections are not fresh evidence.
Follow their original sources instead. Never reinforce a claim merely because
another generated note repeats it. Do not rewrite SOUL/IDENTITY, reactivate
paused work, schedule jobs, contact people, or expand permissions during dreaming.
Immediate memory updates during normal work remain necessary; dreaming reconciles
them later. Use the job's configured reporting channel for meaningful corrections
or failures; keep routine no-change runs quiet.
